# 架构与边界

`core/` 提供缓存和网络引擎。`app/` 是完整应用层，包括 Flutter 界面、Rust 原生模块和各平台宿主；应用层不等同于 UI，也不要求所有功能用 Dart 实现。

| 功能 | 核心 `core/` | 应用层 `app/` |
| --- | --- | --- |
| 处理范围 | 域名、路径、资源类型规则 | 展示说明 |
| 代理与回源 | HTTP/HTTPS/SOCKS 接入、直连与上游代理、连接池、TLS、超时和透传 | 解析连接设置并传入明确的上游参数 |
| 资源缓存 | 磁盘格式、校验更新、内存淘汰与恢复、清理和迁移 | 选择目录、容量及操作时机 |
| 实时预载 | 文本资源识别、强弱依赖、战斗窗口、来源组和优先级调度 | 展示计数和状态 |
| CA 材料 | 生成、保存、读取、签发及重新生成 | 系统信任检测、安装、卸载和交互确认 |
| 回源信任根 | 使用调用方提供的证书验证 TLS；不隐式读取系统证书库 | 读取 Windows/Android 等运行环境的信任根并传入核心 |
| 运行配置 | 校验、应用参数，管理引擎启停 | 设置文件、默认值、用户偏好与持久化 |
| 代理凭据 | 在连接时使用 | 保存保护；Windows 使用 DPAPI，Android 使用 Keystore |
| 日志与统计 | 产生事件、运行计数 | 保留策略、启动清理、导出和路径选择 |
| 连通性检测 | 执行网络探测 | 用户触发和结果展示 |
| Windows | 不操作桌面系统设置 | 窗口、托盘、开机启动、凭据保护、CA 信任 |
| Android | 不管理 Android 组件 | 通知、缓存前台服务、独立 VpnService、系统文件选择与证书设置 |
| 调用桥接 | 普通 Rust 库接口 | Dart FFI、JNI、平台通道 |

调用链：Flutter／平台宿主 → `app/native/` → `core/`。Cargo workspace 在根目录统一锁定依赖；Windows 与 Android 都构建 `gbf-flash-cache-app` 原生库，其中链接共享核心。

核心的数据目录锁用于避免多个引擎同时写入同一份数据；应用原生层在核心运行之上协调设置保存与失败回滚。日志文件的生成属于核心，删除策略属于应用。

缓存和日志目录在停止服务后仍保持独占。Unix 同时锁定目录 inode 与锁文件；Windows 持有不共享删除权限的锁文件句柄。清理、导出、迁移通过固定目录句柄操作，并在文件操作及提交前检查目录和锁身份。检测到替换会中止；迁移失败只回滚本次写入，目标身份失效时不继续删除。迁移单个文件先写暂存文件，完整复制并复核身份后才原子发布，不覆盖已有缓存；复制中断的暂存文件可在重试时清理。

这些锁用于遵守同一协议的实例间协作，不是对外部文件修改的安全隔离。外部程序强行替换锁文件并单独锁住新文件，不等于取得目录使用权；检查与单次系统调用也不是原子事务。

目前仅交付 Windows 和 Android。Android 系统代理属于独立的平台模块，其它平台的系统接管不属于当前产品功能。

## 应用内部边界

| 位置 | 单一职责 |
| --- | --- |
| `app/native/src/application/` | 共用设置持久化、日志保留与导出、核心启停及失败回滚、CA 操作流程 |
| `app/native/src/platform/windows/` | DPAPI、开机启动、Windows CA 信任；通过系统库读取信任根 |
| `app/native/src/platform/android/` 与 `AppHost.java` | 宿主从 AndroidCAStore 读取系统及用户信任根，经 JNI 传入应用层；不直接扫描证书目录 |
| `app/native/src/bridge/` | FFI/JNI 编解码、句柄和调用传输；不选择目录或决定设置策略 |
| `app/lib/core_client.dart` | Dart 原生调用传输，库路径和数据目录由宿主提供 |
| `app/lib/platform/windows.dart` | Windows 应用路径、原生客户端配置与文件管理器操作 |
| `app/windows/` 与桌面界面 | Windows 窗口、托盘和系统界面集成 |
| `app/android/.../AppHost.java` | Android 私有目录、调用线程和原生服务句柄生命周期 |
| `app/android/.../NativeCore.java` | JNI 协议转换，不管理应用生命周期 |
| `app/android/.../CacheService.java`、`MainActivity.java` | Android 普通前台服务、通知、系统文件选择与 URI 写入 |

平台能力通过编译期模块选择提供，公共应用流程不包含 Windows/Android 条件分支；不引入插件注册或动态平台对象。相同流程复用，系统实现按平台归属，并允许继续使用原有 Rust、Java 和 Dart 实现。

Android 通过 Keystore 加密保存代理密码，通过系统界面管理 CA；提供可选的 Android 系统代理模块，但不提供开机启动。`platform/unavailable.rs` 明确表达不支持的能力，不以明文保存等方式降级。其它宿主仅用于本地验证，不表示新增产品平台。

## Android 系统代理模块

`ProxyService` 管理授权、应用范围、前台通知和 TUN 生命周期；`ProxySettings` 独立保存三种范围与两份名单。`platform/android/capture.rs` 持有转发运行时，`forwarder.rs` 用 ipstack 处理 TCP/IP，用 hickory-proto 处理虚拟 DNS，再将 TCP 转到现有回环网关。Android 独有依赖不进入 Windows 发行库。缓存、调度、统计、上游和连接池由共享核心处理。

停止缓存前等待系统代理停止；单独停止或撤销系统代理不停止缓存服务。应用自身 UID 不进入接管。应用范围和用户配置见 [使用说明](../README.md#使用说明)。

TCP、UDP 支持 IPv4 和 IPv6。虚拟 DNS 同时处理 UDP/TCP 53；A 查询分配本次接管内稳定的虚拟 IPv4 地址，转发时还原域名；AAAA 等查询返回空记录。已有真实 IP 或绕过虚拟 DNS 的请求仍可转发，但可能无法按域名进入缓存。

SOCKS5 UDP 保持 UDP ASSOCIATE 控制连接，按指定中继转发；系统代理启动前检查关联，失败不自动直连。HTTP/HTTPS/SOCKS4 上游不承载 UDP，对应 UDP 直接出站。TUN MTU 为 65535；超限数据报失败，不截短或拆成多条数据报；不支持 SOCKS5 分片扩展及 ICMP 转发。

两份应用名单独立保存，系统按 UID 应用范围，共享 UID 的应用会同时受到影响。QUERY_ALL_PACKAGES 仅用于本机选择，不发送应用列表。上游检查和系统代理启停使用独立串行队列，不占用核心状态查询队列。

## 主站请求边界

允许为正确代理转发进行必要的连接和协议处理，不要求整份报文逐字节一致。主站请求保留原始路径、查询参数、方法和正文；连接优化不构成修改游戏请求内容的授权。影响兼容性的变更需单独评估。资源及场景识别只读分析，不重放游戏操作。CDN 缓存规则与范围外流量转发由共享网关区分，用户可见范围见 [使用说明](../README.md#使用说明)。
